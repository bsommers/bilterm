# Phase 50.1 Context: Unified Registry & Find

Source: user request 2026-11-05, inserted ahead of Phase 51.

## Request (verbatim intent)
Inject a set of "find" commands: search for agents, terminal sessions, and command history within terminal sessions. Implies a searchable registry of agents, terminals and command histories. Must extend to connected SSH and tmux sessions.

## Standing process decision
Maximally autonomous: dispatch subagents with maximum parallelism, explicit sonnet/haiku models for planning, research before execution.

## Interactions
- Phase 51 palette-parity test will require `:find` verbs to have palette entries (plan the entries here, not there).
- Existing: `:search` (scrollback), Phase 41 per-pane command persistence, `agent_statuses()`, SSH domains (Phase 18), tmux -CC (Phase 11).

## User decisions (2026-11-05, locked)
- D-U1: `agent`, `session`, `history` are reserved first words of `:find`; any other `:find <text>` stays a scrollback search (`:search` still works for words that collide).
- D-U2: secrets are masked and NOT searchable. Implementation default: secret-looking and password-prompt commands are never stored or indexed (dropped); anything already in `history.log` that looks secret is masked on read and excluded from the index. Surface a count ("n masked") rather than the text.
- D-U3: `:find session` prefers live in-memory sessions (ranked first) and can also search disk (saved sessions, history.log); every result states WHERE it was found (`source`: live / saved-session file / history log, with path or session name), in the UI row, `:find` output, RPC and MCP results.
