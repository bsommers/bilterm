## 1. Decisions

User (locked, `50.1-CONTEXT.md`):
- **D-U1** `agent`, `session`, `history` are reserved first words of `:find`; any other `:find <text>` stays scrollback search (`SearchQuery`, byte-identical); `:search <word>` still works for colliding words.
- **D-U2** Secret-looking and password-prompt commands are never stored or indexed. History already on disk that looks secret is masked on read and excluded from the index. Only a count ("n masked") is surfaced, never text.
- **D-U3** `:find session` ranks live in-memory sessions first and can also search disk (saved-session files, history.log). EVERY result carries `source` (live | saved-session | history-log, with session name and path): in the UI row, the `:find` status/data, RPC and MCP.

Planner decisions (defaults; the user may override before execution):
- **P-01** Commands typed in raw mode (full-screen apps, remote shell raw input, a hand-run `tmux`/`ssh` inside a pane) are NOT recovered this phase (no OSC 133 B-to-C screen scrape). Documented as gap G4.
- **P-02** `:tmux attach` is NOT added: it needs a new `Action` with the full UNI-R01 surface set, the `ssh -T` vs `-tt` question is unresolved (research B A1), `TmuxControlBridge::new()` hard-maps `%0` to pane 1, and nothing can be probed without live tmux. The bridge stays unreachable from production (gap G1). Bridge panes are still indexed whenever `tmux_control` is attached (tests use `TmuxControlSubprocess::from_channels`). `:ssh-tmux` panes become metadata-only rows (`metadata_only = true`, gap G2).
- **P-03** `history.log` lines gain optional header fields `host=`, `transport=`, `cwd=` (percent-encoded values) written at submit time. The exit code is not known at submit time, so `exit=` is written as a separate annotation line (section 8). Legacy readers ignore both.
- **P-04** Secret-looking commands stay in the in-memory `prompt.history` and `vt.command_blocks` (Ctrl+R and block navigation unchanged, Harmony rule) but are never written to `history.log` or the registry ring. Password-prompt input is recorded nowhere (not in `prompt.history`, blocks, `history.log` or the ring); it is still written to the PTY. Residual: because secret-looking commands stay in `prompt.history`, a saved-session file written by `:session save`/autosave can still contain them; they are masked on read (D-U2) and the user guide says so. Override option for the user: also drop secret-looking commands from `prompt.history` (changes Up-arrow recall; not the default because of the Harmony rule).
- **P-05** Group order is `Live` before `SavedSession` before `HistoryLog`; fuzzy score orders rows within a group (realises D-U3 "live ranked first").
- **P-06** Modal-control verbs live under `:finder` (so `:find <word>` keeps its meaning); the key entry is the global chord `Ctrl+Alt+F` (wins over raw passthrough) only: leader `?` is already `Action::HelpToggle` (keymap.rs:65) so Find gets NO leader entry, UNI-R01 is met by menu, colon, palette, RPC, MCP and the global chord; mouse entry is the menu bar View items.
- **P-07** No config knob for the secret pattern list this phase (hard-coded list in `src/pane/redact.rs`, no new crate).

## 3. Types (`src/wm/registry/types.rs`)

```

pub const CMD_CAP: usize = 512;              // chars per stored command (sanitize_display)
pub const NAME_CAP: usize = 64;              // chars per label/title/host
pub const FIND_RESULTS_CAP: usize = 200;     // rows returned/rendered
pub const FIND_DEFAULT_LIMIT: usize = 50;    // RPC/MCP default
pub const FIND_QUERY_CAP: usize = 128;       // chars of query
pub const FIND_HISTORY_READ_CAP: usize = 20_000;   // newest history.log lines read
pub const HISTORY_LOG_BYTES_CAP: u64 = 16 * 1024 * 1024;   // tail window read from history.log
pub const SAVED_SESSIONS_CAP: usize = 64;    // session TOMLs / history dirs inspected
pub const SAVED_FILE_BYTES_CAP: u64 = 2 * 1024 * 1024;
pub const PANES_PER_SESSION_CAP: usize = 64;
pub const PANE_OUTBOX_CAP: usize = 64;       // CapturedCommand per pane between ticks

pub struct ResultSource { pub origin: Origin, pub name: String /*workspace session name*/, pub path: Option<String> /*sanitised absolute path; None for live and in-memory snapshots*/ }
   // label(): "live" | "saved:<name>" | "log:<name>"   (UI tag, always shown)

    pub fn run_find(&mut self, kind: FindKind, query: &str, limit: usize) -> FindResults;  // 01 glue (see below): clears the per-open candidate cache, gathers, ranks
    pub fn rerank_find(&mut self, kind: FindKind, query: &str, limit: usize) -> FindResults;  // 01: ranks the CACHED candidates of `kind` (gathers once, lazily, when that kind has none); used for every keystroke and kind switch

    pub fn find_results(&self) -> &FindResults;  pub fn set_find_results(&mut self, r: FindResults);   // 01
    pub fn is_find_visible(&self) -> bool;  pub fn find_modal_state(&self) -> Option<(FindKind, &str, usize)>;   // 01

```
`RegistryState` keeps the per-open candidate cache (`cached: [Option<Vec<FindRow>>; 3]`, one slot per kind) next to the `DiskCache`; `masked` for a result is `capture masked_live + DiskCache.masked()` and is stored with the cached slot.
`run_find` glue: refresh agent states when `!agents.has_updated()` (as `:agents list` does); take the `DiskCache` out of `self.registry` with `std::mem::take`, gather `live::candidates`, `capture::candidates` (History), `saved::candidates` (Session/History), restore the cache; `masked = capture masked_live + cache.masked()`; call `rank::search(rows, query, limit.clamp(1, FIND_RESULTS_CAP))`. Dedupe by session name for Session rows (highest origin wins, others go to `also_in`) is done in `run_find` after gathering. The query is truncated to `FIND_QUERY_CAP` chars.

Tick hook: `WindowManager::tick` (src/wm/mod.rs, next to `tick_agent_ui`) calls `registry::capture::tick(self, Instant::now())`.

Pane outbox: `CompositePane` owns `captured: Vec<CapturedCommand>` (private) plus `pub(crate) fn drain_captured(&mut self) -> (Vec<CapturedCommand>, u32 /*masked since last drain*/)` and `pub(crate) fn record_history_exit(&mut self, command: &str, exit_code: i32)`. `CapturedCommand { command (sanitised, <= CMD_CAP), at: Instant, cwd: Option<String>, host: Option<String>, block_row: Option<usize> }`.

## 5. Colon grammar

```
:find agent|agents [text]        -> Action::Find(FindOp::Open { kind: Agent,   query })
:find session|sessions [text]    -> Action::Find(FindOp::Open { kind: Session, query })
:find history [text]             -> Action::Find(FindOp::Open { kind: History, query })
:find <anything else> | next|prev|off|clear|prefill|n|p   -> unchanged (SearchQuery / SearchNext / ...)  [D-U1]
:finder kind agent|session|history|next|prev   -> FindOp::SetKind / CycleKind(true|false)
:finder query <text>                           -> FindOp::SetQuery(text)
:finder move <+n|-n|top|bottom>                -> FindOp::Move(i16)   (top = i16::MIN, bottom = i16::MAX)
:finder select <n>                             -> FindOp::Select(usize)  (0-based row index)
:finder enter                                  -> FindOp::Activate
:finder prefill                                -> FindOp::Prefill
:finder close                                  -> FindOp::Close
```
Bare `:finder` is a usage error. Keyboard text editing (`Push(char)`, `Pop`, `ClearQuery`) has the committed twin `:finder query <text>`; `ClearQuery` also has `:finder query` with empty text.

```
pub enum FindOp { Open { kind: FindKind, query: String }, SetKind(FindKind), CycleKind(bool), SetQuery(String), Push(char), Pop, ClearQuery,
                  Move(i16), Select(usize), Activate, Prefill, Close }
```
`Modal::Find { kind: FindKind, query: String, selected: usize }`; results live in `RegistryState` (`find_results()`), not in the enum.

## 7. Output shapes (D-U3: `source` everywhere)

Envelope (returned by `find.*`, stashed by `:find ...` via `set_command_data`, wrapped by the MCP tool):
`{"kind":"session","query":"x","total":12,"returned":10,"truncated":false,"masked":3,"rows":[ROW,...]}`.
ROW common keys: `id`, `kind`, `row` (`agent|session|pane|history`), `label`, `detail`, `score`, `source` (`{"kind":"live|saved-session|history-log","name":"<session>","path":null|"<abs path>"}`), `also_in` (array of `source` objects), `transport`, `host`, `tmux_session`, `tmux_window`, `tmux_pane`, `tags`, `metadata_only`, `pane`, `session`. Per row: agent `state`,`since_ms`,`profile`; session `active`,`pane_count`,`parent`; pane `title`,`cwd`,`cwd_trusted`,`running_command`; history `seq`,`command`,`exit_code`,`duration_ms`. Secret text is never serialised; `masked` is a number only.

UI row tag (always shown, right aligned): `[live]`, `[saved:<name>]`, `[log:<name>]`. The footer line of the selected row shows `source: <origin> <name> <path>`. The status message after `:find` reads `Find <kind> "<query>": <n> results[, <m> masked] (<n_live> live, <n_saved> saved, <n_log> log)`.

## 8. history.log extension (P-03)

Command line (existing prefix preserved): `[ts | session=S | run=R | pane=N | host=<enc> | transport=<enc> | cwd=<enc>] <escaped cmd>`; each of the three fields is present only when known. `<enc>` is percent-encoding of every byte outside `[A-Za-z0-9._~/@:+-]`. With no meta the line is byte-identical to today.
Exit annotation line (separate line, skipped by every legacy reader because it does not start with `[`): `~exit | session=S | run=R | pane=N | h=<8 hex> | exit=<n>` where `h` is FNV-1a 32-bit of the command bytes. Readers join an annotation to the most recent preceding command entry with the same `(run, pane)` and equal `h` that has no exit yet.

## 9. Redaction rules (D-U2; hand-rolled, no regex crate)

`classify(command)` returns `Empty` (blank), `Colon` (trimmed starts with `:`), `Secret`, or `None`. `Secret` when any of: (a) an assignment `NAME=value` (value non-empty) where NAME contains `password|passwd|secret|token|apikey|api_key|api-key|credential|private_key|access_key` (case-insensitive); (b) a flag `--password|--passwd|--token|--secret|--api-key|--apikey|--auth-token|--client-secret|--access-key|--passphrase` followed by a value or `=`; (c) `-p<non-space>` attached value when the first word is `mysql|mariadb|mysqldump|mysqladmin|sshpass`, or `sshpass -p`; (d) `Authorization:`, `Proxy-Authorization:`, `X-Api-Key:` headers or `Bearer <token>`; (e) URL userinfo `scheme://user:pass@host`; (f) token shapes `ghp_/gho_/ghs_/github_pat_` + 20 chars, `sk-` + 20 chars, `AKIA` + 16 upper-alnum, `xox[abprs]-`, `AIza` + 35 chars, JWT `eyJ...eyJ...`, `-----BEGIN ... PRIVATE KEY-----`; (g) `openssl ... -passin|-passout pass:`, `gpg --passphrase`, `chpasswd`, `htpasswd -b`, and `echo|printf ... | sudo -S`. Plain words (`grep -r password src/`, `git commit -m "rotate token"`) are not secrets. Matching is linear in the command length.
Masking applies at capture (never stored), at every read of `history.log`, and to `SavedPaneState.history` lines. The counter `masked` includes all three.

## 10. Known gaps to document (user guide + `:find` help)

G1 `tmux -CC` bridge not reachable from any command (no `:tmux`); one tmux session at a time. G2 `:ssh-tmux` starts no tmux (local shell with remote label; user-guide 05 line 38 was wrong). G3 remote OSC 133 / OSC 7 bootstrap is never sent, so remote exit code and cwd need a pre-configured remote shell. G4 raw-mode input, hand-run `ssh`/`tmux` inside a pane, and anything before attach are not recorded. G5 a local pane where the user typed `ssh host` is not an SSH pane. G6 `pane_id` is unique per run only; journal restore loses `remote_target`; restored SSH panes are local shells. G7 headless daemon holds no live SSH/tmux PTYs. G8 `cd` tracking and `resolve_cwd()` give a local cwd for SSH panes (registry shows cwd only when OSC 7 reported). G9 tmux format variables `pane_command_*` need a recent tmux (not used this phase). G10 tmux window names are known only after a `%window-renamed` notification (no `list-windows` reply correlation).
