## Deviations from Plan

None of Rules 1-4. Interpretation notes:

1. **Annotated loader is path-only.** Plan 05 exposes no text-level join function, so (per the plan's fallback) `read_log_records` points a `HistoryStore` at the session file and calls `load_entries_annotated`. That reads the whole file, so it is used only when the file is `<= HISTORY_LOG_BYTES_CAP`; above that the newest `HISTORY_LOG_BYTES_CAP` bytes are read directly (first partial line dropped) and parsed with `parse_history_record` (no exit codes). The join logic is not duplicated.
2. **Live-ring dedupe is only unit-tested.** `registry::capture::candidates` is still the plan 10 skeleton, so `current_run_duplicates_of_live_ring_are_skipped` asserts the negative side (an empty ring does not drop current-run lines, other runs kept, pane id trusted only for current-run lines). The multiset matching is covered by `live_set_matches_as_a_multiset`. The end-to-end check (a real ring entry suppresses its log line) needs re-running after plan 10 merges.
3. **`FindRow.pane` is `None` for saved rows** (and for log rows of other runs); `PaneRow.pane` still carries the saved pane id. Plan 12's Activate should key on `source.origin != Live`.
4. **Env isolation:** `cargo test --test phase50_1_find_seam` run directly (outside `scripts/verify.sh`) fails `open_stashes_results_envelope_and_status` on a machine with real saved sessions in `~/.local/state/bilterm/sessions`, because plan 01's test asserts "all rows live" and now sees disk rows. Under `scripts/verify.sh` (72/72) it passes. Plan 01's test should set `session_dir`/`history_dir` to tempdirs (not in this plan's file list, left untouched).
