# Phase 50.1 Plan 08: Find input handling Summary

Find window mouse path: a pure `lower_find_mouse` maps tab chips, `[clear]`, list rows (click = Select+Activate, hover = Select, wheel = Move(+-3)) and footer chips to `Action::Find` ops over the same `find_layout` the renderer uses; keys already lowered via `find_modal_key_action` (01) and are now proven against colon twins.

## What was done
- `src/input/find_modal.rs`: `lower_find_mouse`, `handle_find_modal_mouse` (applies via `wm.apply`, `Handled` when lowered, else `None` so title drag/resize/badges stay generic), `list_viewport_start` (duplicated renderer formula, documented). Hover over the already-selected row returns `Some(vec![])` (T-50.1-17). Wheel is accepted anywhere between the tab row and footer.
- `tests/phase50_1_find_input.rs` (13 tests): lowering, outside-rect `None`, viewport index, handler state tracking, key typing/swallowing (T-50.1-16), `Ctrl+Alt+F` close, parity table, key-table colon forms, entry paths incl. raw passthrough.

## Deviations from Plan
1. [Parity table] Kind switch (Tab vs chip vs `:finder kind next`), move (Down x3 vs wheel vs `:finder move +3`) and select (Down x2 vs hover vs `:finder select 2`) lower to different `Action` values by nature (Cycle vs Set, Move(1) vs Move(3) vs Select). The table asserts equal resulting modal state for all three paths and strict `Action` equality for clear/jump/prefill/close; wheel, hover and row-click `Action`s are additionally asserted equal to their colon-parsed twins.
2. [Viewport test] The plan asked for a test against the rendered rows, but 50.1-07 (row rendering) is not in this branch; the test checks the click index against `list_viewport_start` (the documented renderer formula). Re-check once 07 merges.
3. Signature: kept the 5-argument skeleton `lower_find_mouse(mouse, layout, row_count, selected, kind)` (action text), not the 6-argument must_haves form; `kind` is currently unused (prefixed `_kind`).
4. `Activate`/`Prefill` are still status-only stubs in `execute_find.rs` (plan 12), so parity for them is Action-level.
