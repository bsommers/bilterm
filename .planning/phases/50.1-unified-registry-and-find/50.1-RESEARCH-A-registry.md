# Phase 50.1 - Research A: Existing registries, capture points, registry + `:find` design

Researched: 2026-11-05. Read-only; no source changed. All paths relative to repo root. Claims are `[VERIFIED: file:line]` (file opened this session) unless tagged `[ASSUMED]`.

## 0. Headline findings (read these first)

1. **`:find` already exists and is a scrollback-search alias.** `src/colon_command/parse.rs:271-279`: `"search" | "find" => match parts.get(1).copied() { None | Some("off" | "clear") => SearchOff, Some("prefill") .., Some("next"|"n") .., Some("prev"|"p") .., Some(_) => SearchQuery(parts[1..].join(" ")) }`. Also documented: `src/ui/help_catalog.rs:458` ("alias of :search"), completion `src/pane/completion.rs:380` `(":find", &["next","prev","off"])`, user guide `docs/user-guide/06-keyboard-mouse-and-command-reference.md:224`. Harmony rule says `:search` unchanged and `:find <text>` is today a scrollback search. **Recommendation:** add the three new verbs as reserved first words (`agent|agents`, `session|sessions`, `history`) checked BEFORE the `Some(_)` fallthrough; everything else keeps hitting `SearchQuery` (byte-identical). Cost: a scrollback search whose first word is literally `agent`/`session`/`history` now needs `:search agent ...`. Document it. This is a user decision point (see Open Questions).
2. **No registry exists.** Data is scattered over five places (table in section 1). The registry should be a **derived read-only view built on demand** in `wm`, not a new mutable store, except for one small bounded ring of captured commands (section 3).
3. **OSC 133 carries no command text.** `src/vt/scan_osc_dcs.rs:160-193` handles `133;A/B/C/D` and only extracts the exit code from `D;<n>`. Command text exists only where Bilterm itself submits it: `CompositePane::submit_command` (`src/pane/mod.rs:179-218`). Commands typed directly into a raw-passthrough shell, an `ssh` session, or tmux are NOT captured today. This is the central FND-R03 gap.
4. **Pane ids are not globally stable.** `PaneId` is `usize`, monotonic per `WindowManager` (`next_pane_id`, `src/wm/mod.rs:110,198`), but saved-session restore re-uses ids stored in `SavedPaneState.id` (`src/wm/session.rs:22-23`) and `CommandBlockRecord.index` is renumbered on scrollback eviction (`src/vt/mod.rs:472-478`). A registry id must therefore be `(session_name, pane_id)` for panes and a registry-assigned monotonic `u64` for history entries, never `block.index`.
5. **Redaction gap in `submit_command`.** It records to `vt.command_blocks`, `prompt.history` and `HistoryStore` unconditionally (`src/pane/mod.rs:190-215`) with no `is_password_prompt()` check; callers guard (`wm/v2_runtime.rs:46`, `wm/session.rs:334-337`), but `pane.exec` with `allow_echo_lock=true` (`src/api/rpc.rs:306-316`) writes the password-prompt input into history. The registry must not widen this; add the guard at capture (section 4).

## 2. Recommended registry data model and location

**Location:** new `src/wm/registry.rs` (types + builders, <=~600 lines) and `src/wm/registry_find.rs` (matching/ranking + `FindOp` execution, <=~500) with `pub mod registry; pub mod registry_find;` added to `src/wm/mod.rs:1-18` (currently 894 lines; do not grow it - ARCH-R04 soft 800-1000). State field: one `pub(crate) registry: registry::RegistryState` on `WindowManager` (same shape as `agents` `wm/mod.rs:132`, `traffic` `:134`), fields private inside the type (ARCH-R02). Accessors `pub fn registry(&self) -> &RegistryState` only for read; mutation only via `pub(crate)` methods called from `WindowManager` code (capture hook, find modal ops). Do **not** add public fields to `WindowManager`.

**Principle:** `RegistryState` stores only (a) the bounded captured-command ring and (b) find-modal UI state. Agents, panes, sessions are produced on demand by `WindowManager::registry_snapshot(&self) -> Registry` (read-only, `&self`), pulling from `agent_statuses()`, `panes()`, `fleet()`, `tmux_bridge`, `daemon_state.session_tree`, `list_sessions()` (cached via the drawer's `cached_saved_sessions` idea `drawer.rs:240`; do not hit the disk per keystroke).

```rust
// src/wm/registry.rs  (proposed; names ASSUMED)
#[derive(Clone, Copy, Debug, PartialEq, Eq, PartialOrd, Ord)]
pub enum SourceKind { Local, Ssh, Tmux, SshTmux, Saved }       // from remote_target/fleet/tmux_bridge/SavedPaneState

#[derive(Clone, Debug, PartialEq, Eq, Hash, PartialOrd, Ord)]
pub enum EntryId {                                              // stable ids
    Agent(PaneId),                       // agent == tracked pane (live session only)
    Pane { session: String, pane: PaneId },
    Session(String),
    History(u64),                        // registry-assigned monotonic seq, survives block eviction
}

pub struct AgentEntry   { pub pane: PaneId, pub name: String, pub state: AgentState, pub since_ms: u64,
                          pub profile: Option<String>, pub source: SourceKind, pub host: Option<String>, pub title: String }
pub struct SessionEntry { pub name: String, pub active: bool, pub parent: Option<String>, pub pane_count: usize,
                          pub source: SourceKind, pub panes: Vec<PaneEntry> }   // panes: live for active, SavedPaneState for others
pub struct PaneEntry    { pub id: PaneId, pub title: String, pub cwd: Option<String>, pub running_command: Option<String>,
                          pub source: SourceKind, pub host: Option<String>,    // fleet destination / "host/tmuxsession"
                          pub tmux_pane: Option<usize>, pub tags: Vec<String> }
pub struct HistoryEntryView { pub seq: u64, pub session: String, pub pane: Option<PaneId>, pub host: Option<String>,
                          pub cwd: Option<String>, pub command: String,       // already sanitised+capped
                          pub exit_code: Option<i32>, pub duration_ms: Option<u64>,
                          pub age: Recency, pub origin: HistOrigin }          // Live | Persisted
```
- `Recency`: live entries carry `Instant` (monotonic, matches `TrafficEvent.at` convention `traffic.rs:104-106`); persisted ones carry the ISO string from `HistoryEntry.timestamp`. Rank tie-break by recency (as `fuzzy_history.rs:73-77` does).
- `source`/`host` derivation (all verified fields): `pane.remote_target()` is `Some("user@host")` for SSH or `Some("user@host/session")` for ssh-tmux (`session.rs:238,260`); `tmux_bridge.bilterm_to_tmux.contains_key(&id)` => `Tmux`; title prefix is NOT reliable, use these structured sources. Tags from `FleetNode.tags` via `fleet.nodes` where `SshPane.pane_id == id` or `SshTmux.pane_ids` contains it.
- Registry is **session-scoped to the live WM** plus saved-session snapshots; `Registry` is a plain owned struct built per query (<= a few hundred rows; cheap). No locking.

**History model:** two sources merged by `registry_snapshot`/`find history`:
1. *Live ring* `RegistryState.cmds: VecDeque<CapturedCmd>`, cap `CMD_RING_CAP = 2048` (mirror `TRAFFIC_CAP=512`, `traffic.rs:11`; larger because commands are short and history is the point), per-entry `command` capped at `CMD_CAP = 512` chars via `crate::vt::sanitize_display(raw, CMD_CAP)` (`vt/codec.rs:188`, strips control/bidi chars) - the same helper traffic uses (`traffic.rs:183`). Entry: `seq, pane, session, cwd (tracked_cwd at submit), host (remote_target at submit), at: Instant, exit_code/duration_ms: Option` updated when the matching `CommandBlockRecord` finishes (join on `(pane, absolute_row)`).
2. *Persisted file* via existing `HistoryStore::load_entries()` for the active `history_session` (bounded 100k, `history_store.rs:15`). Read lazily, only on `:find history` open, capped to the newest `FIND_HISTORY_READ_CAP = 20_000` lines (use `.rev().take(n)`), never per keystroke (cache in `RegistryState` for the modal's lifetime, drop on close). Dedupe against the live ring by `(run_id == current_run_id(), pane, command)`.

No new on-disk store is needed for FND-R01..03. Optional later (not recommended in this phase): add `exit=`/`cwd=`/`host=` fields to the `history.log` line - requires changing `parse_history_line` which splits on `" | "` and `strip_prefix` (`history_store.rs:105-126`); unknown fields are ignored so adding fields is backward compatible, but older binaries mis-parse `] ` splits only if the command contains `"] "` - already handled by `split_once("] ")` on the first occurrence. Keep out of scope; document as follow-up.

| Surface | Captured today | Capture point | Notes |

**Recommended hook design (ARCH-R02-clean):** `CompositePane` gains a private `captured: Vec<PendingCapture>` outbox (or returns a value) filled inside `submit_command` after the existing recording; `WindowManager` drains it. Simpler and equally chokepoint-safe: since `WindowManager::panes` is private and all pane mutation by the WM is in-module, the registry **drains each pane's new `vt.command_blocks()` suffix during `update_agent_states`/redraw tick** (the `track_finish` pattern already diffs `command_blocks().len()` against `h.last_blocks`, `agent_state.rs:272-296`). Prefer this: no change to `CompositePane::submit_command` signature or the ARCH-R02 rule "command submission goes exclusively through `CompositePane::submit_command`"; the registry watches blocks, keyed per-pane by a high-water `seen_total` (block count can shrink on eviction `vt/mod.rs:472`, so track `(last_absolute_row, last_command)` rather than `len`). Caveat: ticks may batch two commands - fine, both are pushed in order. Caveat 2: password-time input is invisible to this path only if the guard below holds.

## 4. Bounds and redaction (requirements for FND-R04 tests)

Bounds (constants in `registry.rs`, each with a test pushing `cap + N` entries and asserting `len() == cap`, mirroring `TrafficBus` eviction `traffic.rs:195-198`): `CMD_RING_CAP=2048`, `CMD_CAP=512` chars/command, `FIND_RESULTS_CAP=200` rows returned/rendered, `FIND_HISTORY_READ_CAP=20_000` file lines, `NAME_CAP=64` (as `TITLE_MAX_CHARS` navigator.rs:231), query length cap (e.g. 128 chars). RPC `find.*` takes `limit` (default 50, clamp to `FIND_RESULTS_CAP`).

Redaction (all `[ASSUMED]` policy, grounded in existing mechanisms):
1. **Never capture while `pane.is_password_prompt()`** (`pane/scroll.rs:519`; `LineDisciplineState::is_password_prompt` = `!echo_enabled && (canonical || fg-subcommand || osc133_executing)`, `pty/line_discipline.rs:53-56`) or `pane.is_read_only()`. Evaluate **before** `submit_command` runs (after the write the state is already the child's). With the block-watching design in section 3 evaluate at block-detect time AND in `submit_command`: add a one-line guard in `submit_command` that skips `vt.record_command_submission` + `history_store.record_command` when `is_password_prompt()` (this fixes the `pane.exec allow_echo_lock=true` leak, finding 5). This is a behaviour change to existing code - flag it as a deliberate, test-covered bug fix; existing tests: `pane/tests.rs:54`, `input/tests.rs:9`.
2. Store a `redacted: bool` + `REDACTED_PREVIEW = "[redacted]"` pattern (`traffic.rs:25,183-184`) for entries that must remain countable but not searchable; `:find history` never matches redacted bodies.
3. Heuristic secret scrub on the captured text (defence-in-depth, since `!ECHO` cannot see e.g. `export TOKEN=abc`, `curl -H "Authorization: ..."`, `mysql -pSECRET`): drop or mask commands containing `password|passwd|secret|token|api[_-]?key|authorization|bearer|-p<nonspace>` assignments. `[ASSUMED]` list - needs a user-confirmed policy (sensitive; do not present as verified). Provide `[find] redact_patterns` config extension point; default on. Apply at capture and again at display of persisted file entries (the existing `history.log` already contains such lines because `submit_command` records all commands - search over it must scrub at read time).
4. Colon commands (`:`-prefixed) excluded by default.
5. Over RPC/MCP the same scrubbed/capped text is returned; `find.history` over API respects `[api]` gating just as `pane.read` does. `[ASSUMED]`: treat history as at least as sensitive as `pane.read` output; reuse whatever gate `pane.read` has (planner to check `rpc.rs` `pane.read` arm at `:337+`).
6. Control chars: all text through `sanitize_display` before storage and before rendering (modal output must not carry ESC, bidi overrides - `codec.rs:188-206`).

## 5. Persistence via secure_fs

- **Default: no new files.** Ring is memory-only (same as traffic bus, "memory only" per Phase 50 decision), persisted history is the existing `history.log` (already `0700`/`0600` via `private_open_options`, compaction temp+rename `history_store.rs:439-452`).
- If a persisted registry snapshot is wanted later (e.g., `:find` across restarts for agents/hosts): write JSON with `crate::secure_fs::write_private_file(path, bytes)` (`secure_fs.rs:160`, atomic `0600`) into `private_dir_in(&private_runtime_dir()?, "registry")` (`:92,129`); validate any user-supplied name with `validate_plain_file_name` (`:282`; the journal re-wraps it as `validate_safe_name`, `journal.rs:25-31`). Reuse `WorkspaceJournal` conventions (`wm/journal.rs:1-9`). Not required for FND-R01..04; recommend deferring.

## 6. Result-list UI and Action design for `:find agent|session|history`

**Grammar:**
```
:find agent [text]     (aliases: agents)
:find session [text]   (aliases: sessions)
:find history [text]   (alias: cmd, commands?) [ASSUMED]
:find <anything else>  unchanged -> SearchQuery   (parse.rs:271-279 Some(_) arm)
:find next|prev|off|clear|prefill|n|p   unchanged
```
Optional host filter `host:<h>` / `pane:<id>` / `exit:fail` tokens are v2 [ASSUMED]; keep grammar minimal for planning.

**Action design (mirror `AgentsOp`):** `src/wm/find_cmd.rs` `FindOp` enum lowered by `Action::Find(FindOp)` (new variant near `Action::Agents`, `action.rs:181`; sample entry near `:599`; `colon_command` mapping `ColonCommand::Find(FindOp)` handled at `execute_wm.rs:835`-style arm; sub-parser `src/colon_command/parse_find.rs` modelled on `parse_agents.rs:1-60` with a `USAGE` const). Proposed ops (all executed through `WindowManager::apply`, ARCH-R01):
- `Open { kind: FindKind, query: String }` - the colon verb; builds results, sets `Modal::Find{..}`, sets status message summary and `set_command_data(json)` with the result rows (so RPC/`bilterm ctl wm.command` get data exactly as `:agents list` does, `execute_agents.rs:274-282`).
- `Query(String)` / `Push(char)` / `Pop` - typing in the modal (what `input/modal.rs:880-919` does for palette, but via Action).
- `Move(i32)` / `PageMove(i32)` / `Select(usize)` - Up/Down/PgUp/PgDn/click.
- `CycleKind` (Tab) - agent -> session -> history.
- `Activate` (Enter / double-click) - jump (below), closes modal.
- `Close` (Esc).
Key table: put in `src/input/keymap.rs` as `FIND_MODAL_BINDINGS` with the same drift/no-shadow tests as `AGENTS_WINDOW_BINDINGS` (`keymap.rs:368+`); mouse in `input/mouse_wm.rs` next to the palette handling (`:250-300`), both lowering to `FindOp`. Entry keys: a leader/chord is optional (Phase 51 parity requires a palette entry only); suggest palette entries `:find agent`, `:find session`, `:find history` (put in `PALETTE_CATALOG` + `HELP_LINES` + `COLON_COMMANDS` now, per CONTEXT "plan the entries here"). Update completion `(":find", ...)` at `completion.rs:380` to `["next","prev","off","agent","session","history"]` and add `(":find agent", &[])`-style rows only if the table pattern requires.

**Modal:** add `Modal::Find { kind: FindKind, query: String, selected: usize }` (exclusive-modal rule `ARCH-R02.4` doc at `wm/mod.rs:64`); results are NOT stored in the enum (recomputed from `registry_snapshot` + query each render, like `filtered_palette_items()`), but the history file read is cached in `RegistryState` while open. Cascade of required edits (each a compile error if forgotten, so low risk): `wm/mod.rs` Modal match sites, `z_stack.rs:415-480` `active_modal_rect` default size (copy Palette's `clamp(24,76) x clamp(6,14)`; history rows are wider, use `clamp(40,100)`), `ui/mod.rs:732` render dispatch, `ui/modals.rs` new `render_find_modal` (copy `render_palette_modal` `modals.rs:70-155`; row layout per kind below; use `Span`s so matched indices can be bold - `pattern.indices` as in `fuzzy_history.rs:46`), `input/modal.rs` key arm, `input/mouse_wm.rs`.

Row formats (single line, sanitised, cap per `NAME_CAP`):
- agent: `#<pane> <name> [<state>] <host|local> <since>` (state glyph per navigator).
- session: `<name> (*active) <n panes> <parent?>`; expand to panes via Right/Tab - v2.
- history: `<age> #<pane> <host|local> <cmd>` + exit code badge if known.

**Ranking:** one shared helper `rank<T>(items: &[T], haystack: impl Fn(&T)->String, query) -> Vec<(u32, usize /*idx*/, Vec<u32> /*matched indices*/)>` in `registry_find.rs`, generalising `filtered_palette_items` (`session.rs:86-120`) and `FuzzyHistorySearchState::recompute` (`fuzzy_history.rs`): `Matcher::new(Config::DEFAULT)` reused across items (palette allocates one per call, fine), `Pattern::parse(q_lower, CaseMatching::Ignore, Normalization::Smart)`, `catch_unwind` around `pattern.score/indices` (both existing sites do; keep), fallback substring score 100/subsequence 10 (`session.rs:123-130`), sort score desc then recency desc (history) / pane id asc (agent). Empty query: recency order. Haystack = name + title + host + state (agents); session name + pane titles + hosts + cwd (sessions); command + cwd + host (history). **Do not reimplement matching a third time** - extract and have the palette and fuzzy-history call the helper only if their tests stay byte-identical (otherwise leave them untouched per Harmony rule and only share via a new function). Recommend: new helper, leave existing two untouched.

**Jump semantics (`Activate`):**
- agent -> `focus_and_raise(pane)` (`wm/mod.rs:737`); if pane vanished, status message "pane #N is gone".
- session (active) -> focus its active pane; session (saved) -> `switch_or_create_session(name)` (`session_manager.rs:341`) which autosaves outgoing and restores (fall back to status error if `Err`). Mark that this changes state (autosave) in docs.
- history -> if entry's pane is live: `focus_and_raise(pane)` and, when a `CommandBlockRecord` still matches `(absolute_row)`, scroll to it (new `pub` fn on `VtParser` wrapping private `scroll_to_command_block`, `vt/mod.rs:733`, or `set_scrollback_offset`, `:755`); if the pane is gone or entry is persisted-only: close modal and optionally pre-fill the active pane's prompt with the command (`:find prefill` analogue; `Action::SearchPromptPrefill` exists, `action.rs:339-340` neighbourhood) - never auto-execute. Persisted entry from another run: show only; Enter pre-fills.
- All paths close the modal, set a status message via `active_pane_mut().set_status_message(..)` (used throughout, e.g. `execute_agents.rs:226,297`).

**RPC/MCP (FND-R04):** add `"find.agents"`, `"find.sessions"`, `"find.history"` to `RPC_METHODS` (`rpc.rs:25-46`, drift-tested against dispatcher) with params `{query, limit}`; implement as thin dispatcher arms that call `registry_snapshot()` + `registry_find::search(..)` (read-only, no Action needed for pure queries; but the interactive modal open path stays an Action). ## 7. SSH and tmux coverage (FND-R03) - what is and is not possible

| Item | Searchable | Source | Gap |
|---|---|---|---|
| SSH pane host, tags, connected | yes | `FleetNodeKind::SshPane`, `remote_target()` | - |
| SSH pane commands typed in prompt | yes | `submit_command` | not for raw-mode keystrokes or commands run inside a remote tmux/screen |
| SSH-tmux session name | yes | `FleetNodeKind::SshTmux.session_name`, `remote_target = "dest/session"` | no window/pane names, `connect_ssh_tmux` spawns no PTY (`session.rs:247-282`) |
| Local tmux -CC panes | pane existence + `%id` | `tmux_bridge.tmux_to_bilterm` | window/session names: only `active_session_name` (`tmux/mod.rs:241`); window names not parsed; would need `list-windows -F` queries over the control channel (new outbound command) `[ASSUMED]` |
| Commands inside tmux panes | no | - | `%output` bytes only; gap to document |
| Remote exit codes | only with OSC 133 on remote | `133;D` | requires remote bootstrap; document |

Document these gaps in the user guide chapter and `:find` help text; do not claim command capture for raw/remote-typed input.

## 8. Risks / pitfalls for the planner
- `:find` verb collision (finding 1): the existing alias test list in `command_registry.rs`/help drift tests may assert `:find` is alias of `:search`; check `command_registry.rs` `EXTRA`/alias tests before editing (grep `":find"` shows only `help_catalog.rs:458` and `completion.rs:380` in src, so edit those two and docs line 224).
- `Modal` is matched exhaustively in 4 files (compile-time safe); but `active_modal_rect` default-size arm and `ui/mod.rs` render dispatch are easy to forget for non-compile-checked behaviour (e.g. `super::Modal::None | Menubar => return None` at `z_stack.rs:473`).
- Palette Enter path (`input/modal.rs:889-921`) bypasses `Action` - do not copy it; Find must route through `apply` (Harmony rule).
- `update_agent_states` is the only place agents are refreshed; `:find agent` must refresh when stale (as `execute_agents.rs:237`) or results lag by one tick.
- `fleet` is private with `fleet()/fleet_mut()`; `tmux_bridge` is `pub(crate)`, reachable from `wm/` modules.
- File-size: `wm/mod.rs` 894, `wm/session.rs` 800, `execute_wm.rs` 867, `parse.rs` 721, `modals.rs` unknown - put new code in new files (`registry.rs`, `registry_find.rs`, `find_cmd.rs`, `parse_find.rs`, `execute_find.rs`) to stay under the 1200 backstop (`tests/vt_worker_and_snapshot_seam.rs:208`).
- Headless tests: `WindowManager::new_headless(cols, rows)` + `CompositePane::new_headless(id, title, cols, rows)` (CLAUDE.md). Fleet nodes can be registered without a PTY (`register_ssh_pane`, `remote/mod.rs:291`; test `session.rs:779-785` shows `spawn_ssh_pane` works headless).
- History persisted file includes every submitted line including colon commands and any pre-existing secrets; read-time scrub (section 4.3) is mandatory.
