- `crate::input::drawer_herdr::{handle_herdr_drawer_key(wm, key) -> Option<AppAction>, handle_herdr_drawer_mouse(wm, mouse, dr, workspace_area) -> Option<AppAction>, HERDR_DRAWER_KEYS}`.

Key choices (Claude's discretion, verified free): `e` fold, `!` attention, `r` prefills `:drawer rename ` (herdr analogue of classic `r`).

Colon verb collision (verified at commit 0915792): `parse_drawer_command` already maps `minimize | min | hide | close` to `ColonCommand::DrawerSize(0)` (src/colon_command/parse_visual.rs:692), so `:drawer close` means "minimize the drawer" today and must keep that meaning (harmony rule). The herdr pane-close verb is therefore `:drawer close-pane`; the `x` / Delete keys lower to `DrawerNavOp::Close` exactly as before. None of the other new verbs (`next|down`, `prev|up`, `enter|activate|select`, `fold`, `new-session`, `new-pane|new-window`, `rename`, `close-pane`) is an existing `:drawer` verb or alias.

Key-table exception (ARCH-R01; AGENTS.md Conventions item 1, line 157: "all keyboard shortcuts live in declarative `KeyBinding` tables in `src/input/keymap.rs`"). `HERDR_DRAWER_KEYS` lives in `src/input/drawer_herdr.rs`, not in keymap.rs. This is a deliberate, documented exception:
- keymap.rs holds the surface-independent tables (`DEFAULT_LEADER_BINDINGS`, `DEFAULT_GLOBAL_BINDINGS`, `DEFAULT_PANE_BINDINGS`) that map a chord straight to an `Action`. The herdr table is consulted only while the herdr drawer holds keyboard focus, and some entries depend on drawer state (`j`/`k`/Up/Down only without SHIFT/ALT so classic session moves still work; `r` prefills the prompt, which is input-local state, not an `Action`; 50-12 adds Right, which claims a row only when it has a comms indicator). Focus-local key handling already lives outside keymap.rs today: the focused-drawer, `:mcp` console and modal blocks in src/input/modal.rs.
- Every state-changing entry still lowers to `Action::DrawerNav` via `wm.apply`; `handle_wm_key_event` is not edited; the global entry point (leader `!`) stays in keymap.rs (50-04).
- The exception is recorded where readers will see it: the module doc comment of src/input/drawer_herdr.rs starts with `//! Key-table exception (ARCH-R01):` followed by these reasons, and the SUMMARY lists it under decisions.
