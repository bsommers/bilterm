## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| remote API client -> `remote.link` / connect methods | untrusted JSON from any transport (socket, TCP, loopback HTTP with bearer token, MCP) |
| params -> colon string -> parser | string assembly is the injection surface |
| link summary -> API client | remote-derived text leaves the process |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-51.1-18 | Tampering / Elevation of Privilege | command injection through `op`, or an API client making Bilterm start `ssh` to an arbitrary host | high | mitigate | closed op set, the colon string built only from the validated op; connect keeps `validate_destination`; the capability equals existing `remote.connect_ssh` (already starts ssh) and is recorded in the SUMMARY; a second link is refused (P-01) |
| T-51.1-19 | Information Disclosure | link summary exposing argv, identity paths or raw remote text | low | mitigate | the summary holds flags, counts, ids and the sanitised `%exit` reason and tail only (test `link_json_keys_are_stable` asserts the key set; no argv key exists) |
| T-51.1-SC | Tampering | cargo installs | high | mitigate | no dependency change; `git diff --exit-code HEAD -- Cargo.toml Cargo.lock` |
