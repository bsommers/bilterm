## 1. Decisions

No decision is locked by the user (`51.1-CONTEXT.md` lists none). Planner defaults below are what the plans implement; the user may override before execution. Open user inputs (non-blocking, they only sharpen docs/troubleshooting): the exact command typed after `:ssh-tmux`; whether `tmux ls` on the Mac still shows the session after a drop; any `client_loop` / `closed by remote host` text.

- **P-01 One link at a time.** The WM keeps one `tmux_control` and one `tmux_bridge` (unchanged). `:ssh-tmux` while a link is `Connecting`, `Connected` or `Backoff` returns `Err` ("a tmux link to <dest>/<session> is already active; run :ssh-tmux disconnect first") and creates no pane. Multi-link is a follow-up (needs a bridge per link).
- **P-02 Real transport.** `:ssh-tmux` spawns `ssh -tt ...` in a PTY (`PtySession`) running `tmux -CC new-session -A -s NAME`. The PTY is not a visible pane. Until the DCS sentinel `ESC P 1000 p` arrives, the stream is ordinary terminal text (ssh banner, host-key question, password prompt, errors): it is rendered into the link's primary pane and that pane's keystrokes go to the PTY raw. After the sentinel the stream is control lines.
- **P-03 No ControlMaster for the link.** `ControlMaster=no`, `ControlPath=none`: every (re)connect opens a fresh TCP connection (debug hypothesis 5).
- **P-04 macOS PATH.** One remote argument, valid for POSIX sh, bash and zsh login shells (fish accepts it too; csh/tcsh unsupported, documented): see section 5.
- **P-05 Auto-reconnect.** Capped exponential backoff 1, 2, 4, 8, 16, 30, 30... s, no jitter (determinism), at most 20 attempts, attempt counter reset after 30 s of stable connection. Never retried: Fatal failures (auth, host key, missing tmux), user disconnect (`Detached`), remote session ended (`Ended`).
- **P-06 `%exit` classification.** Reason stored verbatim (sanitised). Transient when the reason contains (case-insensitive) `server exited unexpectedly`, `lost tty`, `too far behind` or `connection`; any other `%exit` (none, `detached`, `exited`, ...) is `Ended`.
- **P-07 Disconnect keeps panes.** `disconnect`, `Ended`, `Failed` and `Backoff` keep the mapped panes with a banner (scrollback is not lost). Reconnect re-adopts them by the reconcile rule (section 7). The remote tmux session is never killed by Bilterm.
- **P-08 Drop the seed.** `TmuxControlBridge::new()` is empty. The first discovered tmux pane adopts the link's primary pane (the placeholder created by `connect_ssh_tmux`); further panes come from `insert_tmux_pane`. Tests that encoded the `%0 -> pane 1` seed are updated by plan 05.
- **P-09 Hydrate.** After the attach greeting, one `capture-pane -p -e -J -S -2000 -t %N` per mapped pane and one `refresh-client -C COLSxROWS`; replies are correlated FIFO (section 7). No `list-panes -F` reply parsing this phase (50.1 gap G10 stays).
- **P-10 Remote PTY panes (`:ssh`).** A pane with `remote_target().is_some()` whose PTY exits is held with a banner (exit code, last output line) regardless of pane count. Local panes keep today's behaviour (reaped when more than one pane exists).
- **P-11 Restore honesty.** `remote_target` is re-applied only when the respawned program's basename is `ssh`; otherwise it is dropped, the title gains ` (not connected)` and a status message names the saved target. Journal restore is unchanged (50.1 gap G6).
- **P-12 Exit code.** `PtySession::exit_code(patience)` polls `try_wait` every 2 ms for at most `patience` (hold path passes 50 ms); never blocks longer.
- **P-13 Reserved words.** `reconnect`, `disconnect`, `info`, `prefill` are reserved first words of `:ssh-tmux`/`:sshtmux`. A host with such a name is reached as `user@name` or through a `:remote add` alias.
- **P-14 API.** New method `remote.link` (closed `op` set `status|reconnect|disconnect`), new MCP tool `bilterm_remote_link`; `remote.connect_tmux` and `remote.connect_ssh {tmux_session}` return `status: "connecting"` plus `state` and `link` (honest). `prefill` has no API path (UI-only). No write gate involved (no configuration is written); like `remote.connect_ssh` today these methods start an `ssh` child.
- **P-15 No new dependency.** `Cargo.toml` / `Cargo.lock` are untouched in this phase. `RemoteHostProfile` gains no field (a struct literal in `tests/drawer_classic_parity.rs` would break).
- **P-16 Keys.** `Ctrl+Alt+R` (global, also in `reserved_global_action`) = `Reconnect`; leader `u` = `Prefill`, leader `U` = `Reconnect`, leader `Q` = `Disconnect`. 51.1-01 re-reads the live tables and, on a real conflict, takes the next free chord and records it; tests read the tables, never hard-code a chord. Banner keys (only while the banner is interactive): `Enter`/`r` reconnect, `x` disconnect, `d` detach client.

## 4. Control stream (`ControlLineSplitter`, plan 03)

`push(&mut self, bytes: &[u8]) -> Vec<SplitOut>` with `SplitOut { Raw(Vec<u8>), ControlStart, Line(String), ControlEnd, Dropped(usize) }` (`Dropped` = a control line over the cap was discarded; the number is its length). Rules: before control mode every byte is `Raw`. Control mode starts at `ESC P 1000 p` (the sentinel may be split across chunks, nothing before it is lost) or, fallback for hosts that omit it, at a raw line that starts with `%begin ` or `%output `. In control mode bytes accumulate to `\n`; the line is emitted without a trailing `\r\n`/`\n`, invalid UTF-8 replaced lossily; a line longer than `CONTROL_LINE_MAX` is dropped (one diag line). `ESC \` (ST) ends control mode (`ControlEnd`); later bytes are `Raw` again. `diag_lines(raw: &[u8]) -> Vec<String>` turns raw text into sanitised non-empty lines (`sanitize_display(.., DIAG_LINE_CAP)`).

## 6. Link state machine (pure, fake clock, plan 04)

`backoff_delay_ms(policy, attempt)`: attempt 0 is 0; attempt n >= 1 is `min(cap_ms, base_ms * factor^(n-1))` (1000, 2000, 4000, 8000, 16000, 30000, 30000...). Transitions (`now` in ms):

| State + event | Result | Commands |
|---|---|---|
| Idle + Connect | Connecting{since=now, awaiting_control=true} | Spawn |
| Connecting + ControlStarted | Connected{since=now} | MarkConnected |
| Connected/Connecting + Down(d), class Transient | if connected for >= stable_after_ms then attempt = 0; attempt += 1; attempt > max_attempts: Failed; else Backoff{attempt, retry_at = now + delay(attempt)} | MarkDown{retry_in_ms} or MarkFailed |
| ... class Fatal | Failed{attempts: attempt} | MarkFailed |
| ... class Ended | Ended | MarkEnded |
| ... class User | Detached | MarkDetached |
| Backoff + tick(now >= retry_at) | Connecting | Spawn |
| any + UserDisconnect | Detached | KillTransport, MarkDetached |
| any + UserReconnect | attempt = 0, Connecting | KillTransport (when a transport may exist), Spawn |
| Backoff/Detached/Ended/Failed/Idle + Down | ignored (stale transport) | none |

`classify_exit(cause, reason, code, tail) -> ExitClass`: UserDetach is User; SpawnFailed is Fatal; ControlExit by P-06; Eof/ProcessExit: tail line containing (case-insensitive) `permission denied`, `host key verification failed`, `no matching host key`, `command not found`, `no such file` is Fatal; code `127` is Fatal; `connection refused`, `timed out`, `broken pipe`, `connection reset`, `closed by remote host`, `could not resolve hostname`, `network is unreachable` is Transient; `ProcessExit(Some(255))`, `Eof`, `ProcessExit(None)` with no other evidence is Transient; `ProcessExit(Some(0))` (remote command ended normally without `%exit`) is Ended.

`disconnect_text(&TmuxDisconnect) -> String` (cause text used in banners and status lines: `tmux exited[: reason]`, `connection closed`, `ssh exited {code}[: first tail line]`, `spawn failed: {err}`, `stopped by user`). `link_banner_text(state, target, exit, policy, now_ms) -> Option<LinkBanner>`: `None` for Idle and Connected. Texts (plain ASCII, `sanitize_display`ed, <= 160 chars): Connecting: `LINK CONNECTING {dest}/{session} | type here for ssh prompts | Ctrl+Alt+R: restart` (interactive: false); Backoff: `LINK DOWN ({cause}) | retry {n}/{max} in {s}s | Enter/r: now | x: stop | d: detach`; Failed: `LINK FAILED ({cause}) | Enter/r: retry | d: detach`; Detached: `LINK STOPPED | Enter/r: reconnect | d: detach`; Ended: `REMOTE SESSION ENDED | Enter/r: start a new one | d: detach` (all but Connecting are interactive: true).

Status lines (also used by tests): connect `Connecting to {dest} (tmux session '{session}')...`; up `Connected: tmux '{session}' on {dest}`; transient `Link to {dest} lost ({cause}); retry {n}/{max} in {s}s`; fatal `Link to {dest} failed: {cause}`; ended `Remote tmux session '{session}' on {dest} ended`; detached `Disconnected from {dest} (tmux session '{session}' kept on the remote)`; headless without transport `Link {dest}/{session}: no transport (headless)`. No status or title produced before `ControlStarted` contains `Attached` or `Connected`.

## 7. Bridge, hydrate and I/O rules (plans 05, 06, 12, 13)

- **Adoption.** `connect_ssh_tmux` creates the primary pane (headless, via `split_focused`), sets title `TMUX-SSH:{dest}/{session} [#id]`, `remote_target = "dest/session"`, `bridge.set_primary(id)`. The first tmux pane the bridge discovers (`%output`, `%layout-change`, `%window-pane-changed`) maps to it; the pane is reset (`ESC c`) and retitled `TMUX-SSH:{dest}/{session} %{n} [#id]`. Any other new tmux pane goes through `insert_tmux_pane` and gets `remote_target = "dest/session"` and the TMUX title.
- **Reconcile on reattach.** `reset_for_attach` moves the current mappings to a stale set, clears `exited`, exit reason and pending replies. A rediscovered tmux id that was mapped before keeps its pane; a new id adopts the lowest-numbered stale pane first; a new id with no stale pane creates a pane. `finish_reconcile` (called when the hydrate phase reaches `Done` or after the first `%layout-change` settles) returns stale panes that were never re-adopted (orphans): they stay, with the banner `REMOTE PANE GONE | close with :close`, never auto-removed.
- **WindowClose.** `%window-close @W` (and `%unlinked-window-close`) removes the window's tmux ids from the maps and queues their Bilterm panes in `take_removed_panes`; the WM removes them through `WindowManager::remove_pane` (never the last pane; the primary is kept, with the banner, when it is the last).
- **Exit.** `%exit [reason]` stores the reason, sets `exited`, and `poll_tmux_control` calls `on_tmux_control_down(TmuxDisconnect{cause: ControlExit, reason, ..})` once. Channel EOF without `%exit` is `Eof`. `tmux_control` is dropped only after the disconnect is recorded; nothing is silent.
- **Replies.** Every command Bilterm writes (`send-keys`, `split-window`, `refresh-client`, `capture-pane`) is queued with a `ReplyKind` (`Ignore` for all but capture) and enters the `ReplyCorrelator` FIFO when written. A block that starts while the FIFO is empty is the attach greeting and is discarded. Body lines between `%begin` and `%end`/`%error` belong to the head of the FIFO. `PENDING_REPLIES_CAP` bounds it; overflow clears the FIFO and logs.
- **Hydrate.** `HydratePlanner`: `AwaitingGreeting` until the first `EndBlock`/`ErrorBlock`, or `GREETING_GRACE_MS` after the first line; then `Ready`: the WM sends `refresh-client -C {cols}x{rows}` and `capture-pane -p -e -J -S -2000 -t %N` per mapped pane (`Sent`); when every capture replied, `Done`. While a capture for pane N is pending, `%output %N` is dropped (it is already contained in the snapshot, tmux sends no notification inside a block); the reply is fed as `render_capture` (lines joined with `\r\n`, trailing blank lines dropped, no trailing newline, no cursor-addressing sequences) and live output resumes. The hydrate command batch waits until at least one tmux pane is mapped and 300 ms passed since the last newly mapped pane (multi-window layouts arrive in bursts).
- **Input.** A pane with the remote-input tap on converts its `write_to_pty` bytes: while the link is `Connecting` (awaiting control) they go raw to `driver.write_raw`; when `Connected` and the pane is mapped they become `send-keys -t %N -H xx ..` in chunks of `SEND_KEYS_CHUNK`; otherwise they are dropped with a status message. The primary pane is in raw input (`set_link_raw_input(true)`) while awaiting control, so a typed password is never in `prompt.history`, `history.log` or the registry ring.
- **Resize.** On attach and when `default_size` changes: `refresh-client -C`, and `driver.resize(rows, cols)`.
- **Order inside `tick_tmux_link`.** driver pump (lines into the channel, raw output into the primary pane) -> `poll_tmux_control` -> removed panes -> input pump -> outbound pump (writes commands, registers FIFO kinds) -> reply pump (hydrate, apply captures) -> machine tick (backoff Spawn) -> banners and status. `poll_all_ptys` calls it once, replacing the bare `poll_tmux_control` call; `tick_tmux_link` still calls `poll_tmux_control` internally so existing tests that call `poll_all_ptys` keep working.
- **Generations.** Every spawn increments `generation`; events from an older transport are ignored.
- **Fleet.** `register_ssh_tmux` is re-run when the mapped pane set changes (`pane_ids` = primary + mapped panes); `FleetNode.connected` mirrors `Connected`.

## 8. Pane additions (seam fields, plan 07 refinements)

`CompositePane` gains: `remote_input_tap: bool`, `remote_input: Vec<u8>` (`REMOTE_INPUT_CAP`, excess dropped), `link_banner: Option<LinkBanner>`, `exit_code: Option<i32>`. `write_to_pty` appends to `remote_input` when the tap is on (after recording `last_pty_write`). ## 9. Colon grammar and Actions

```
:ssh-tmux <dest|profile> [session]        -> Action::SshTmuxConnect (unchanged)
:ssh-tmux | list | ls | status             -> Action::RemoteList (unchanged)
:ssh-tmux reconnect                        -> Action::RemoteLink(RemoteLinkOp::Reconnect)
:ssh-tmux disconnect                       -> Action::RemoteLink(RemoteLinkOp::Disconnect)
:ssh-tmux info                             -> Action::RemoteLink(RemoteLinkOp::Info)      (data verb: set_command_data(link_summary_json))
:ssh-tmux prefill                          -> Action::RemoteLink(RemoteLinkOp::Prefill)   (prompt text becomes ":ssh-tmux ")
:sshtmux ...                               same (existing alias); extra arguments after reconnect/disconnect/info/prefill are a usage Err
:respawn-pane / Enter on a held pane       -> Action::RespawnPaneInPlace -> WindowManager::respawn_active_pane (link banner => link_reconnect; held remote pane => respawn; else legacy)
```
`RemoteLinkOp { Prefill, Reconnect, Disconnect, Info }` (`Clone, Copy, Debug, PartialEq, Eq`), `colon_form(&self) -> &'static str`. `Action::RemoteLink(RemoteLinkOp)`; sample `:ssh-tmux info`; listed in `every_action_is_reachable_from_keymap_colon_or_rpc`. Headless fixtures with no link never panic or error, so the `api_conformance` catalog sweep can run the palette examples; the exact statuses are `No tmux link to reconnect (use :ssh-tmux <dest> [session])` (Reconnect), `No tmux link to disconnect` (Disconnect) and `No tmux link (use :ssh-tmux <dest> [session])` (Info, which also stores the idle summary as command data).

## 13. Rules for parallel executors

1. Edit only the files your plan lists; `git add` by path, commit `type(51.1-NN): ...`; never `git add -A`, never revert another plan's file. 2. The tree is shared (`workflow.use_worktrees` false): the crate compiles after each save; a compile error in a file you do not own: retry once, then report. 3. Task checks use `cargo test -q --test <name>` (always `-q`); the closing check of a plan that runs alone may use `scripts/verify.sh --only ...`. 4.
