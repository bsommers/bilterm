## 5. Six-Step Manual UAT Script for the User's Mac (`bill@bigmac.local`)

Run this checklist on the Linux desktop against `bill@bigmac.local` where real `ssh` and `tmux` are available:

1. **Interactive Connect & Prompt Privacy (`PST-01`)**:
   - Start Bilterm with debug logging: `RUST_LOG=bilterm=debug bilterm`
   - Run `:ssh-tmux bill@bigmac.local uat`
   - Verify the primary pane shows the `LINK CONNECTING bill@bigmac.local/uat` banner and status `Connecting to bill@bigmac.local (tmux session 'uat')...` (never `Attached`).
   - If prompted for a host key or password/passphrase, type it directly in the pane; verify the link transitions to `Connected: tmux 'uat' on bill@bigmac.local`, the banner clears, and `:find history` does **not** contain any typed credential.
2. **Verify Remote Persistence (`PST-01`)**:
   - In the linked pane, run `echo "hello-from-mac-$$"` and `tmux ls`.
   - Confirm `uat: 1 windows (attached)` is running on `bigmac.local` (including when `tmux` lives in `/opt/homebrew/bin/tmux`).
3. **Simulate Network Drop & Observe Backoff (`PST-02`)**:
   - Drop the SSH connection (e.g., on the Mac run `pkill -f "tmux -CC new-session -A -s uat"` or kill the `sshd:` child process, or toggle Wi-Fi briefly).
   - Verify the pane stays open with the interactive banner `LINK DOWN (...) | retry 1/20 in Ns | Enter/r: now | x: stop | d: detach` and live countdown.
4. **Automatic Reconnect & `capture-pane` Hydrate (`PST-02`)**:
   - Let the backoff timer fire (or press `Enter` / `r` / `Ctrl+Alt+R` or click the banner).
   - Verify the same Bilterm pane is reused (no duplicate panes), `hello-from-mac-$$` is restored via `capture-pane` hydration, and new keystrokes (`uptime`) execute on the Mac.
5. **Intentional Disconnect Keeps Remote Session (`PST-02`)**:
   - Run `:ssh-tmux disconnect` (or press `Ctrl+X Q`).
   - Verify the banner shows `LINK STOPPED | Enter/r: reconnect | d: detach`, and on the Mac `tmux ls` still shows session `uat` alive. Press `r` to reattach cleanly.
6. **Session Save/Restore Honesty & Plain `:ssh` Hold (`PST-03`)**:
   - Run `:session save uat-mac`, restart Bilterm, and run `:session restore uat-mac`.
   - Verify the restored local shell pane does **not** wear a fake remote badge, its title ends with `(not connected)`, and its status explains how to reconnect (`:ssh-tmux bill@bigmac.local uat`).
   - Also test `:ssh bill@bigmac.local`, then type `exit`: verify the pane is held with `REMOTE SESSION ENDED (code 0): ... | Enter/r: reconnect | d: detach | :quit!: exit` instead of vanishing.

## 6. Open User Questions from `51.1-CONTEXT.md` & Effect of Answers

1. **What exact command was typed after `:ssh-tmux`?**
   - *Effect*: If you passed a second positional argument that collided with the new subcommands (`reconnect`, `disconnect`, `info`, `prefill`), those four words are reserved subcommands; naming a tmux session one of those words requires quoting or choosing another session name.
2. **Does `tmux ls` on the Mac still show the session after a drop?**
   - *Effect*: If `tmux ls` shows no session after a drop, `~/.tmux.conf` on the Mac likely sets `exit-empty on` or `destroy-unattached on`, which tells tmux to destroy the session when the SSH client disconnects. Our `%exit` classifier treats clean server exit as `Ended` (no infinite reconnect loop); removing `destroy-unattached on` on the Mac keeps the session persistent across drops.
3. **Was there any `client_loop: send disconnect` or `Connection closed by remote host` message?**
   - *Effect*: Confirms whether the drop originates from NAT/firewall idle timeout (now mitigated by `ServerAliveInterval=15` and `ServerAliveCountMax=3` on both `:ssh` and `:ssh-tmux` plus `ControlPersist=10s` on `:ssh`) vs macOS sleep (`pmset -g`).
