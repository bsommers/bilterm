<task type="auto">
  <name>Task 1: Build declarative Action keymap tables, dual-leader detection, tmux/herdr chords, and held-Ctrl normalization</name>
  <files>src/input/keymap.rs, src/input/mod.rs</files>
  <action>
    1. In `src/input/keymap.rs`, define declarative lookup tables (`default_leader_action(key: KeyEvent) -> Option<Action>` and `default_global_action(wm: &WindowManager, key: KeyEvent) -> Option<Action>` backed by `DEFAULT_LEADER_BINDINGS` and `DEFAULT_GLOBAL_BINDINGS` tables) covering all WM and Pane shortcuts.
    2. Update `is_leader_key(key: KeyEvent, leader_cfg: &str)` and add `is_leader_key_with_tmux(key: KeyEvent, leader_cfg: &str, inside_tmux: bool) -> bool`:
       - When `leader_cfg` is the default `"Ctrl+X"` (or `"Ctrl+B"`):
         - If `!inside_tmux`, accept BOTH `Ctrl+X` and `Ctrl+B` as the leader prefix!
         - If `inside_tmux` (`$TMUX` detected), accept `Ctrl+X` (so `Ctrl+B` passes through to outer `tmux` without collision).
       - If the user configured a custom `leader_cfg` (e.g., `"Ctrl+A"`), match `leader_cfg` plus `Ctrl+X` fallback.
    3. Add `tmux`/`herdr` post-leader chords to `DEFAULT_LEADER_BINDINGS`:
       - `"` -> `Action::SplitHorizontal`
       - `%` -> `Action::SplitVertical`
       - `n` -> `Action::DeckNext`
       - `p` -> `Action::DeckPrev`
       - `H` -> `Action::HistoryPopupToggle`
       - `R` -> `Action::RecordStart { path: None, workspace: true }`
    4. Fix held-`Ctrl` chord swallowing in `handle_wm_leader_key` / `handle_pane_leader_key`:
       - When `key.modifiers.contains(KeyModifiers::CONTROL)` on the follow-up key after the leader:
         - If `c` is `'x'` or `'b'` (double-tap leader `Ctrl+X Ctrl+X` or `Ctrl+B Ctrl+B`), send literal control byte (`0x18` or `0x02`) in `RawPtyPassthrough` mode, or `Ctrl+A` moves cursor home in `CommandPrompt` mode.
         - If `c` is `'q'`, return `Ok(AppAction::Quit)`.
         - Otherwise, strip `KeyModifiers::CONTROL` (`KeyEvent::new(KeyCode::Char(c), key.modifiers - KeyModifiers::CONTROL)`) and look up the chord in `default_leader_action`! That way holding `Ctrl` during `Ctrl+X Ctrl+V`, `Ctrl+X Ctrl+H`, `Ctrl+X Ctrl+Z`, `Ctrl+X Ctrl+O`, `Ctrl+X Ctrl+T`, `Ctrl+X Ctrl+E`, etc. works seamlessly!
    5. Simplify `handle_wm_key_event` in `src/input/mod.rs` to route through `wm.apply(action)` and stay well under 80 lines (`ARCH-R01.2`).
  </action>

    <automated>cargo test --lib input:: && test $(awk '/^pub fn handle_wm_key_event/,/^}/' src/input/mod.rs | wc -l) -le 80</automated>
  </verify>
  <done>`handle_wm_key_event` is `<= 80` lines, declarative keymap tables drive all shortcuts via `wm.apply(action)`, and dual-leader + held-`Ctrl` chords work.</done>
