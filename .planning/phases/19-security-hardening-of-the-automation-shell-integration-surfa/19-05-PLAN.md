<objective>
Confine `workspace.snapshot` `ppm_path` for RPC/MCP clients to a designated snapshot directory (SEC-R02, D-02, D-03), and validate SSH destinations at the two registration entry points (SEC-R04 defence in depth).

Purpose: an RPC client can currently write a PPM to any path the daemon user can write (e.g. overwrite `~/.bashrc`).
Output: confined/trusted snapshot writers, `snapshot_dir` on `AutomationControlPlane`, trust-aware playbook execution, MCP runner taking a plane, validated `fleet.register` and `:remote add`.

Note on D-02: `playbook.run` is reachable over RPC and MCP (`bilterm_run_playbook`) with client-supplied TOML. D-02 makes playbooks unconfined because they are "operator-authored, local"; an RPC-submitted playbook is neither, and D-02 also states "only RPC/MCP clients are confined". This plan therefore keeps the CLI `--playbook` path (and the public `run_playbook` used by the existing test) unconfined and confines only the RPC/MCP `playbook.run` path. This matches CONTEXT D-02 "Amended 2026-10-23 (user)" (RPC/MCP-submitted playbooks are confined; only CLI `--playbook` is trusted), and the bare-file-name rule (`sub/x.ppm` rejected) matches D-03 "Amended 2026-10-23 (user)".
</objective>
