Action-lowering rule (ARCH-R01; project CLAUDE.md: "All user-triggerable commands/keybindings/RPC calls lower to `crate::action::Action` and execute via `WindowManager::apply`"; AGENTS.md Conventions item 1: "all keyboard shortcuts live in declarative `KeyBinding` tables in `src/input/keymap.rs`"):
- The navigator key table lives in src/input/keymap.rs next to the existing tables: `pub enum DrawerKeyScope { Navigator }` (Clone, Copy, Debug, PartialEq, Eq; 50-12 adds `NavigatorComms`), `pub const NAVIGATOR_DRAWER_BINDINGS: &[(DrawerKeyScope, KeyModifiers, KeyCode, Action)]`, and `pub fn navigator_drawer_action(scopes: &[DrawerKeyScope], key: KeyEvent) -> Option<Action>`: scopes are tried in the given order (most specific first); modifiers are compared with SHIFT removed for `KeyCode::Char` (like `default_pane_action`) and exactly for other codes, so Shift/Alt+Up/Down never match the plain arrow rows and keep their classic session-move meaning.
- `src/input/drawer_navigator.rs` only resolves the active scopes from drawer state, looks the key up and calls `wm.apply(action)`. A source gate in Task 2 checks that the only `wm.` calls in src/input/drawer_navigator.rs are `apply` and read-only accessors.
