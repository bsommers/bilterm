## Bilterm control rules for AI agents

You are running inside (or driving) Bilterm, a terminal multiplexer with a control plane. Use its
structured interfaces instead of screen scraping or blind `sleep` loops. This text is generated by
`bilterm agents-md` (same text: MCP resource `bilterm://agents-md`, RPC `agent.guide`).

### 1. Pick an interface
- **CLI** (always available in a pane): `bilterm agent|pane|workspace|coords ...` and
  `bilterm ctl <METHOD> [JSON_PARAMS]`. Inside a pane `BILTERM_SOCKET` already points at the right
  instance and `BILTERM_PANE_ID` is your own pane (excluded from `@` selectors).
- **MCP** (`bilterm --mcp`): tools `bilterm_workspace_status`, `bilterm_inspect_pane`,
  `bilterm_exec_command`, `bilterm_send_keys`, `bilterm_colon_command`, `bilterm_agent_control`,
  `bilterm_agent_mail`, `bilterm_fleet_exec`, `bilterm_daemon`; resources `bilterm://state`,
  `bilterm://pane/<id>`, `bilterm://commands`, `bilterm://agents-md`.
- Every colon command below (they start with `:`) also runs through
  `bilterm ctl wm.command '{"command":":split v"}'` or MCP `bilterm_colon_command`.
  `bilterm://commands` (or `:commands`) lists them all.

### 2. Daemons and targeting
- `bilterm daemon list` shows running daemons; `bilterm daemon start NAME`, `bilterm daemon stop NAME`
  and `bilterm daemon status NAME` manage one (default name `default`, own socket per name).
- Target a named daemon with `--daemon-name NAME` (after `ctl`, `agent`, `pane`, `workspace`,
  `coords`, `daemon`) or `BILTERM_DAEMON=NAME`. A named target is never auto-started or swapped
  for another daemon; if it is not running, start it or report that.
- In-app: `:daemon list`, `:daemon status`, `:daemon start`, `:daemon stop`, `:daemon switch NAME`.
- Never stop a daemon or close panes you did not create unless told to.

### 3. Look before you act
- `bilterm pane list`, `bilterm agent list`, `bilterm workspace list`, `bilterm ctl workspace.status`.
- `bilterm pane read SELECTOR` (MCP `bilterm_inspect_pane`) returns `lines`, `alternate_screen`,
  `echo_lock`, `read_only` and OSC 133 `command_blocks` (`command`, `exit_code`, `duration_ms`).
- SELECTOR: `w<N>:p<M>`, `p<M>`, `<id>`, `@claude`, `@agy`, `@idle`, `@working`, `@blocked`,
  `@done`, `@errored`, `@focused`.

### 4. Run things and wait for them
- Shell command: `bilterm ctl pane.exec '{"pane_id":1,"command":"cargo test -q"}'` (MCP
  `bilterm_exec_command`). Then read `exit_code` from the newest `command_blocks` entry, or poll
  `bilterm ctl events.poll '{"drain":true}'` for `command_completed`. Do not sleep and hope.
- Full-screen program (`alternate_screen: true`: vim, htop, less): raw keys with
  `bilterm pane send SELECTOR TEXT --enter` or MCP `bilterm_send_keys`.
- `echo_lock: true` is a password prompt and `read_only: true` is a locked pane: writes are
  refused. Never put a secret on a command line or in a message to get past it.

### 5. Other agents
- Prompt one: `bilterm agent prompt SELECTOR TEXT`. Wait: `bilterm agent wait SELECTOR --until idle`
  (states `idle|working|blocked|done|errored|attention`). Read its answer:
  `bilterm agent last-turn SELECTOR`. Answer its permission prompt: `bilterm agent approve SELECTOR`.
- Mailbox messaging (off until `:agent enable on`): `:agent name NAME` registers a pane,
  `:agent send NAME TEXT` (`--nudge` shows a one-line notice, `--file` writes a private file),
  `:agent inbox`, `:agent ack`, `:agent list`, `:agent broadcast TEXT`. RPC `agent.send`,
  `agent.inbox`, `agent.wait`; MCP `bilterm_agent_mail`. Bodies are capped at 8 KiB and rate-limited.
- Queue a prompt for when an agent goes idle: `:agent queue add TEXT`. Shared scratchpad:
  `:context set KEY VALUE`, `:context list`.
- Worktree swarms: `:swarm status`, `:swarm spawn SLUG`, `:swarm run`.
- Hand these rules to another agent: `:agent guide` (focused pane), `:agent guide PANE`,
  `:agent guide all`, or `bilterm agent guide SELECTOR`.

### 6. Windows and panes
- `:split h`, `:split v`, `:focus <pane-id|left|right|up|down|next|prev>`, `:zoom`, `:close`.
- `:layout tiled`, `:layout stack`, `:arrange grid`, `:deck next`, `:deck prev`, `:quake`.
- CLI twins: `bilterm pane split h`, `bilterm pane focus SELECTOR`, `bilterm pane zoom`,
  `bilterm workspace select NAME`, `bilterm workspace new NAME`.
- Fan-out: MCP `bilterm_fleet_exec` or `:broadcast on` / `:broadcast off`.

### 7. Hard rules
- Bearer tokens go in a `0600` file (`-t FILE` or `BILTERM_TOKEN_FILE`), never on argv.
- Config writes over the API (`:set KEY VALUE`, `:config save`, `:appearance save`) are refused unless the
  user set `[api] allow_config_write = true`; do not try to work around that.
- Snapshot and export paths are plain file names inside Bilterm's own directories; `..` and `/`
  are rejected.
